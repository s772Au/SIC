# Rust Core 契约迁移状态

## 当前工作记录（2026-11-10，开发中）

下表是独立 `rust-core` 的现状与证据。后面的逐条表格保留迁移开始时的
基线；其中“初始状态”不是实时结论。状态按当前精简协议核对：单 Editor、
Worker 等待、共同稳定前缀及独立 I 视图。每项都区分代码存在、测试范围和
真实 Provider/DSH 验收；任何一项都不代表生产可用。未完成的外部证据按类别汇总在 `OUTSTANDING-EVIDENCE.md`。

> 外部验收阻塞项见 `EXTERNAL-ACCEPTANCE-BLOCKERS.md`。
>
> **验证快照（2026-11-13）**：F01–F73 全部登记；audit status buckets implemented 22、partial 50、other F63；42 行实时状态、91 个引用文件；`cargo test` 417 项 0 失败，`cargo fmt --check` 通过。测试数不等于契约验收，也不替代真实 Provider/DSH/质量/部署证据。

Worker 的 `retry_worker_http_5xx` 配置默认关闭。显式启用后，对已记录且未
采用响应的 500/502/503/504，DSH bridge 在当轮 Worker 调用预算内按
`worker_retry_max_attempts`（总次数 1–5，省略时保持原有的单次重试）和
`worker_retry_backoff_ms`（首次等待 0–5000 ms，逐次翻倍、上限 5 秒，省略时
250 ms）重试；非法值在启动前报错。这两项取自 CTFy 集成在 `sic2` 中验证过的
配置形状，但这里仍沿用 bridge 层分类，不重试传输连接失败。同一轮 Worker
调用上限提高到 1–64，并可从模型配置 `dsh_bridge.max_worker_calls_per_turn`
读取（`--dsh-max-worker-calls` 优先，非法值在监听前报错）；`tests/service_process.rs`
覆盖 CLI 与配置键两条路径。CTFy 的 `sic_runtime.render_model_config` 现在显式写出
`retry_worker_http_5xx`、`worker_retry_max_attempts: 3`、`worker_retry_backoff_ms: 400`
和该配置键，使镜像内的旧二进制与本主线读到同一份策略。用量不明的调用
保持未知。隔离 mock 已覆盖开关、预算、未派发工具、HTTP 状态、超时、重试次数
与退避，见 `tests/dsh_core_integration.rs`、`tests/provider.rs`。此策略尚未经过
真实 Provider、真实外部工具或断电验收，也不构成未知 turn 的完整恢复。
Worker 的 5xx 与非法 choice 重试都核对失败记录及完整请求、模型配置、输入
和控制状态；并发修改时在调用 Provider 前拒绝。

独立 DSH 启动入口已改为由自身 Core 直接绑定动态端口，并从该子进程获取
端口，避免与其他本机服务争用预探测端口。合成 DSH 命令的隔离启动检查通过；
该变更后的真实 DSH 端到端路径尚未重新验收。

Core 命令行服务先对数据库做只读身份检查，再取得服务锁，最后才以可写方式
打开 Rust 数据库；冲突的第二个服务不会先可写打开该库。隔离进程测试同时
核对未识别数据库不会产生服务锁文件。这项保证针对该命令行入口，直接嵌入
`Store::open` 的宿主仍需自行执行相应的进程级排他控制。

peer watcher 现有界并发与持久失败治理，默认值仍与旧行为一致（每轮 1 个
候选、1 个 supervisor）：`max_tasks_per_cycle` 取 1–8，`max_concurrent_runs`
取 1–4 且不超过前者。终态失败按轮询间隔指数冷却（上限 15 分钟），同一
task/revision 累计 3 次后隔离并输出 `quarantined_awaiting_host_ack`，须由宿主
执行 `sic-peer-supervisor.exe ack` 才能再次检查；`status` 子命令可在不读取
bearer 的情况下查看最多 512 条治理记录（不含任务文字、prompt 或模型输出）。
仍在 `intent`／`running` 的子进程不算失败。`src/peer_watch.rs` 的合成 runner 测试覆盖并发上限、结果
顺序、跨重启冷却、隔离与解除，`tests/peer_watch_cli.rs` 覆盖 `ack` 不读 bearer
的路径。**没有**多个真实 DSH 子进程并发、共用 `dsh_home`／profile 的隔离证据，
因此该并发仍属未验收能力；真实多 peer 工作应先用默认串行配置。
