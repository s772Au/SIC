# SIC Rust Core 快速开始（Windows ARM64）

本文以已解压的 SIC Rust Core 打包目录为当前工作目录。首次使用请为 Rust Core 建立独立数据库；不要把旧 Python 数据库路径传给 Rust 服务。

## 1. 检查程序与 DLL

本次本地包的 `release\sic-core-rust.exe` 使用 `aarch64-pc-windows-gnullvm` 构建。请将随包提供的 ARM64 `libunwind.dll` 和 EXE 放在同一 `release` 目录，并保留其许可证；不能用 x64 DLL 替换。若手头只有源码，可在已安装兼容工具链的环境中构建：

```powershell
cargo build --release --locked
```

使用默认构建目标时，产物位于 `target\release\sic-core-rust.exe`；构建前可用 `rustc -Vv` 查看目标。其他工具链和平台尚未随本包验收。

## 2. 建立 DSH 运行副本

如果当前运行目录的 `dsh-plugin\node_modules` 已存在（例如已准备依赖的本机运行包），可以直接使用当前目录，并跳过本节下面的复制和安装步骤：

```powershell
$PluginDirectory = Join-Path (Get-Location) 'dsh-plugin'
$SicExe = '.\release\sic-core-rust.exe'
```

未安装依赖的源码发布包则需要先用 setup helper 校验并复制只读源包到一个新目录，再只在副本的 `dsh-plugin` 安装 lockfile 固定的生产依赖。helper 会先试本机 pnpm 缓存，失败后使用公共 npm registry；不运行依赖生命周期脚本，不读取 DSH profile，也不把凭据类进程环境变量传给 pnpm。它不会覆盖已有目录或修改源包。

helper 已包含在独立包的 `scripts\setup-dsh-runtime.ps1`。把下面路径替换成已解压且通过校验的包目录，以及一个尚不存在的新绝对目录：

```powershell
$VerifiedPackage = '<已校验的 SIC Rust 包绝对路径>'
$RuntimeDirectory = '<新运行副本的绝对路径；目录必须不存在>'
& (Join-Path $VerifiedPackage 'scripts\setup-dsh-runtime.ps1') `
  -SourceDirectory $VerifiedPackage -RuntimeDirectory $RuntimeDirectory
$PluginDirectory = Join-Path $RuntimeDirectory 'dsh-plugin'
Set-Location $RuntimeDirectory
$SicExe = '.\release\sic-core-rust.exe'
```

后续命令均在 runtime 副本目录执行。保留原包不变，数据库也只在副本中创建。

## 3. 初始化独立数据库

在包目录的 PowerShell 中运行：

```powershell
New-Item -ItemType Directory -Force .\data | Out-Null
& $SicExe init .\data\sic-rust.sqlite
```

请为 Rust Core 选择新的数据库文件。Rust Store 不会原地接管 Python 数据库；旧库应保留为只读源，并先在独立副本上完成检查或迁移。

命令行服务启动时先只读核验数据库，再取得独占服务锁，成功后才可写打开数据库；已有服务持锁时，第二个服务会拒绝启动。直接嵌入 `Store::open` 的宿主须自行实现进程级排他控制。

## 4. 配置模型与环境变量

示例中的 `credential_origin` 将密钥限定到 OpenDesign 的 HTTPS 域名；
如果 `api_base` 被误改到其他域名、端口或协议，程序会在读取密钥前拒绝。
自定义 Provider 时应同时设置对应的 `credential_origin`；省略时没有这项检查。

示例配置在 `config\opendesign.example.json`：它指定 OpenDesign 的 `deepseek-v4.1-flash-eco`、1,000,000-token 上下文、393,216-token 支持上限，以及每次实际请求最多 4,096 个输出 token。支持上限不等于默认实际请求量；修改实际预算时，模型配置的 `default_output_tokens` 与 DSH 的 `maxTokens` 必须一致。

该示例还显式启用 `retry_editor_http_5xx`：Editor 收到明确的 HTTP 500、502、503 或 504 后，可在同一有界编辑尝试额度内延迟重发相同请求。每次调用分别记账；没有返回用量的失败调用记为未知。省略该选项时默认不启用；429、超时、响应丢失、Worker 和外部工具均不因此自动重试。额度耗尽仍需要宿主处理失败任务。

Worker 有独立的 `retry_worker_http_5xx` 配置，示例未启用，省略时默认关闭。显式设为 `true` 后，DSH bridge 仅对明确收到的 500、502、503 或 504 重试，并受当轮 Worker 调用上限约束；`worker_retry_max_attempts` 取 1–5（省略时保持单次重试），`worker_retry_backoff_ms` 取 0–5000（省略时 250 ms，逐次翻倍、上限 5 秒），非法值在启动前报错。Core 必须先记录该失败且未采用响应或派发其中工具。每次请求分别计入账务，未返回的用量记为未知。429、超时、响应丢失和外部工具不重试；该策略仅通过隔离模拟测试，尚未做真实 Provider 验收。

上述重试和非法 choice 的重试在再次调用前均核对具体失败记录、模型配置、输入和控制状态及完整请求摘要；期间状态或请求发生变化会拒绝重试，并保留会话待宿主处理。

Worker 默认将纯文本工具结果按单条最多 32,768 个、合计最多 131,072 个 Unicode 字符分配预览额度，优先保留最近结果；被缩减的结果带来源、摘要和明确不完整标记。原文不被覆盖，可通过 `sic_source_text_page` 分页读取，后续 Editor 仍收到原始材料。宿主可用 `config.update` 设置 `tool_result_preview_chars`：设为 `0` 关闭投影，或设为 `1024` 至 `131072` 调整单条阈值；`tool_result_total_preview_chars` 可设为 `1024` 至 `1000000`。这些是字符数限制，不保证整个请求低于网关字节上限；真实任务中的模型翻页与质量尚未验收。

模型配置可以设置 `reasoning_effort`，包括关闭推理的 `none` 及兼容别名；
SIC 原样透传，不声称各 Provider 对别名的实际映射相同。默认示例不设置此项。
固定 OpenDesign 模型在 `none` 下完成过一次 DSH 合成工具往返，另一次返回
不符合单结果请求的双 choice，已被拒绝；不要把一次成功视作该模式的完整验收。

服务启动前，由宿主环境安全提供两个变量：

- `SIC_RUST_BEARER`：本机 DSH 与 Core 之间的独立访问令牌。
- `SIC_PROVIDER_KEY`：模型服务凭据，模型配置只通过 `api_key_env` 引用变量名。

不要把任何密钥值写进配置文件、命令参数、DSH patch、日志或本说明。模型供应方的价格字段由使用者按自己的 DSH 账户与实际费率配置；本包不提供或推测价格。

## 5. 用本地入口启动 DSH headless

准备好 `SIC_PROVIDER_KEY` 后，可以让入口脚本启动独立 Rust 数据库、隔离 DSH profile 和当前任务。状态目录须为新的空目录，或为该入口之前创建的目录；工作目录须已存在。以下路径按自己的环境填写：

```powershell
& .\scripts\run-dsh-headless.ps1 `
  -StateDirectory '<独立状态目录的绝对路径>' `
  -WorkingDirectory '<工作目录的绝对路径>' `
  -AllowedTools @('read') `
  -MaxWorkerCallsPerTurn 16 `
  -Prompt '在这里填写任务'
```

脚本只把模型配置引用的凭据传给 Core 子进程，DSH 使用单独生成的本机 bearer；任务通过标准输入交给 DSH。默认只开放 `read` 工具名，工具名白名单不限制文件路径；需要其他工具时须显式填写 `-AllowedTools` 并由 DSH 宿主处理相应权限。默认价格是 DSH 必填字段的零占位值，不代表免费；可通过脚本的价格参数配置。使用 `-JsonEvents` 可取得 DSH 的事件流和 `sessionId`，后续调用传入 `-SessionId` 可以恢复同一会话。正常结束后入口停止其 Core 进程并保留状态；异常退出后的未决任务仍须核对，不能假定外部动作已回滚。

入口让自己启动的 Core 直接绑定系统分配的本地端口，并从该进程的启动信息取得端口，避免先探测空闲端口、释放后又被其他程序占用的窗口。端口绑定和健康检查已用隔离的合成 DSH 命令验收；当前版本的真实 DSH 端到端路径仍需再次核验。

`-MaxWorkerCallsPerTurn` 设置一次 DSH 工作轮内的 Worker 模型调用上限，
包括内部工具调用和跨桥接请求的外部工具续接，默认 8、可设 1 至 64；
调高可能增加调用次数和费用。
到达上限会明确报错，已发生的操作不会自动重放，同一请求的完整恢复仍未
实现。直接运行 Core 时对应参数为 `--dsh-max-worker-calls`（1 至 64，优先于
模型配置中的 `dsh_bridge.max_worker_calls_per_turn`；两者都省略时为 8，非法值在
监听前报错）。

入口默认在 Worker 收到完整但 choice 数量不符的响应、且该响应没有被采用
或派发工具时，最多再请求一次；`-MaxInvalidChoiceRetries` 可设为 0 至 2，
0 表示关闭。额外调用仍计入 `-MaxWorkerCallsPerTurn` 和用量；失败结果与
原始响应用于审计。网络超时、429、HTTP 失败和外部工具不会因此自动重试。
直接运行 Core 时可用 `--dsh-invalid-choice-retries`，其默认值为 0。

该入口只创建自己的 DSH profile，不会修改当前 DSH 用户配置。若 OpenDesign 凭据已保存在本机 DSH 中，也可以在上述命令中增加 `-DshCredentialMap @{ SIC_PROVIDER_KEY = 'OPENDESIGN_API_KEY' }`；入口使用已安装 DSH 的凭据解析器读取对应引用，只经内存交给 Core，不会导出到调用方环境。DSH 凭据目录默认为当前 `DSH_HOME` 或用户的 `.dsh`，也可用 `-DshCredentialHome` 显式指定。多个模型密钥使用多个引用映射。完整界面、任意业务工具和生产负载尚未验收。

## 6. 手动启动 Core 与 DSH 插件

在同一个 PowerShell 窗口以前台方式启动 Core：

```powershell
& $SicExe serve .\data\sic-rust.sqlite 127.0.0.1:18930 local-owner SIC_RUST_BEARER `
  --allow-model --model-config .\config\opendesign.example.json --dsh-alias sic-worker
```

将 `local-owner` 换成此实例的宿主身份。监听地址限定为 loopback。该数据库由一个 Core 进程独占；不要同时启动第二个服务实例。

在另一 PowerShell 窗口为已存在的 DSH profile 安装包内插件，并通过宿主环境向该 DSH 进程提供与 Core 相同的 `SIC_RUST_BEARER`：

```powershell
$DshProfile = '替换为要使用的 DSH profile 名称'
$PluginDirectory = Join-Path '<上面创建的 runtime 绝对路径>' 'dsh-plugin'
dsh plugin --profile $DshProfile add $PluginDirectory
```

DSH provider 配置至少要与 Core 地址及输出预算一致。以下价格占位符必须在使用前替换为账户的实际数字费率；不要直接照抄占位符：

```yaml
- id: agent-default-model
  config:
    provider: sic-core-rust
    model: sic-worker
- id: sic-core-rust-dsh
  config:
    provider: sic-core-rust
    baseURL: http://127.0.0.1:18930/v1
    apiKeyEnv: SIC_RUST_BEARER
    model: sic-worker
    maxTokens: 4096
    inputPricePerMillion: <输入价格>
    outputPricePerMillion: <输出价格>
    cacheReadPricePerMillion: <缓存读取价格>
    cacheWritePricePerMillion: <缓存写入价格>
```

插件默认不绑定已有 Agent。只有要把一个自己拥有、空闲且已在 Rust DB 中的 Agent 接到新的 DSH 会话时，才配置 `bindChainId: <已有 chain_id>`。插件会在该进程首次收到会话后先调用本机 `/v1/sic/bind`，成功后才发送模型请求；同一插件进程中一个 `bindChainId` 只能绑定首个 DSH Session。绑定不会导入旧 Python 数据，也不会为其他身份授予访问权限；已有 DSH 会话的历史不能假定可直接迁入。

DSH Web 中打开该会话的 `SIC` 标签，可以查看最近的 WB/CB 发布、原生工具事件和按 Editor／Worker 及模型分组的用量；可按需读取主上下文时间线、CB 内容和决策树，也可新增受支持的决策条目。状态需要点击“刷新状态”重新获取。用量只包含 Provider 实际返回的字段，缺失显示为未知；DSH 自带的单模型用量栏可能显示 0，不能用作 SIC 的总账或账单。此界面目前不是完整的上下文编辑器，具体范围见 `LEAN-ACCEPTANCE.md`。

## 7. 旧数据与隔离队列

不要让 Rust Core 直接打开 Python 服务正在使用的库。需要迁移时，先用只读快照或 SQLite backup 建立独立副本，并按迁移工具报告逐项审查。当前迁移路径会将不支持或无法确认可执行语义的旧运行事件保留为隔离/检疫状态；它们不会因为启动 Rust Core 就自动执行。不要手工把这些事件标成可执行，也不要删除原始库来代替验收。

迁移副本与新建空库应分开保管。未完成转换与验收的对象、权限、工具状态和历史内容不能当作 Rust 中可执行的 Agent 能力。

## 8. 停止服务

先在运行 DSH 的窗口用 `Ctrl+C` 结束当前会话，再在运行 Rust Core 的窗口用 `Ctrl+C` 触发服务的正常关闭。等进程退出后再移动、备份或更换数据库。不要用强制结束进程作为日常停止方法；服务退出或异常结束后才会释放数据库独占锁。

## 当前验收范围

当前版本面向文本输入与文本输出。Core 采用单 Editor 配置；失败后的 claim 恢复及 peer 协作虽有代码与定向验证，尚未作为完整生产流程验收。DSH Web 中上述部分界面使用真实 DSH 和本机模拟模型验收；受控 mock 或有限 live smoke 只证明对应路径完成过，不代表任意工具、长时间自动调度、完整界面或生产负载已经通过验收。
