# Multimodal context on the native SDK path

SIC edits authorized text and preserves original media objects. The reviewed
DSH SDK carries raster images as immutable attachment references and files as
readonly file handles. Its original attachment service, access resolver and
Adapter still own bytes, permissions, upload/reuse, image budgeting and
offload. A file handle is not a new Provider file upload. The reviewed SDK does
not add native audio/video understanding through this integration.

For optional Editor-selected crops, mosaics in I and cited descriptions, see
[IMAGE-COMPRESSION.md](IMAGE-COMPRESSION.md).

Worker and Editor need the same actual media, rather than a textual claim that
the archive contains it. A host-owned readonly media projection carries the
original SDK image/file blocks with their original message and block identity.
Tool-result media also retain the original call association and error flag;
these facts do not prove command success or completion of a background task.
Original user captions and attachment metadata retain user provenance.

Only authorized text leaves enter the editable WB. Media bytes, attachment
references, signed reasoning and tool arguments are not text-edit targets.
Deleting or moving associated text does not delete a media object. Recursive
CB replacement changes the text representation while retaining the native
media projection. Original history remains available for provenance. The
remaining native message points to the shared carrier instead of sending the
same image twice; its call/result envelope remains intact. A host offload
decision is preserved, including its original readonly-path placeholder.

Core-native transactions for Messages, Chat Completions, Responses and the
DSH SDK retain their own original protocol. Unknown media/opaque fields are
preserved, not translated to a different API or represented as newly editable
base64 text. A native block digest identifies its stored JSON object; it does
not establish the current bytes behind a remote URL or an attachment handle.

Acceptance checks must inspect the final original Adapter request after
editing, higher publication, common adoption and recovery, including
image-only input and image-only tool results. Distinguish opaque/reference
preservation, real attachment byte equality and actual model media
understanding. Record unsupported external endpoints or modalities as Provider
capability failures. Local protocol-server success certifies integration,
not an external model's visual quality or support for another modality.
