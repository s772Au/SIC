# SIC 的透明上下文编辑边界

此文件记录用户明确的目标设计。现有实现、历史示例或孤立执行器与其不符时，按目标判断改造缺口，不反过来把旧限制当成 SIC 定义。

## 1. 同一原生协议内完成编辑

```text
Harness 原生请求
  → 解析该协议中的可编辑上下文及不可编辑元数据
  → SIC 编辑／选择活动表示
  → 按原协议重新封装
  → Harness 原有 Provider 调用链
```

Chat、Responses、Anthropic 等分别保持自己的格式，不统一转成 Chat。字段、工具调用和结果关系、reasoning／签名／不透明载体、流事件身份与顺序等，除确实涉及授权上下文编辑的内容外保持原生语义。

未知字段或不能安全编辑的块应保留为不透明原文／不可编辑对象，不因与 SIC 无关的扩展而静默丢弃、改写或强迫换协议。未实现某种上下文编辑路径要如实标记；“透传载体”不能冒充“已能编辑该载体”。

多模态上下文沿宿主原生媒体、附件和工具结果契约处理。区分可编辑文字、不可变媒体对象与引用、带签名或加密的协议载体；保持媒体与来源、调用及所属消息的关联，避免摘要覆盖后静默丢图、断开文件引用或把 base64 当普通文字编辑。原件留档不等于后续 Worker 实际可见，需检查编辑、递归替换和恢复后最终 Adapter 请求中的媒体。媒体字节保真、模型能读取与理解、SIC 可做哪些编辑分别验收；保留宿主权限、附件 offload 和 Provider 能力边界，不另造一套媒体上传或模型路由政策。

续接 ID、远端会话状态和增量请求属于上下文关联，不能一律当作无关元数据。核对目标 Harness 的原生重建／请求系列机制，确认修改后的完整上下文确实生效；保留 API 格式并不意味着继续使用已经过期的续接状态。

## 2. 共享前缀的模型身份

目标是复用同一物理前缀缓存时，Worker／Editor 沿用 Harness 同一 Provider 执行路由、模型与可共享缓存作用域，角色区别由教学与原生可承载的本次激活表达。SIC 不自行给 Editor 改选供应商或模型。

同一 Provider／模型仍不是实际命中证明。若 Harness 主动切换路由、模型或隔离域，那是新的缓存条件，不能继续宣称复用了原物理缓存。既有 logical digest／scope 指标不能替代 Provider 证据。

## 3. 职责划分

| Harness／Provider 原有职责 | SIC 必要职责 |
|---|---|
| API 格式、模型路由、认证、请求选项 | 在对应原协议内定位和重建被授权编辑的上下文 |
| SSE／非流式选择与原生传输 | 不改变选择；观测增量，识别适合冻结／编辑的完整材料边界 |
| n／choice 产生、选择与采用政策 | 保留全部原生返回；需要记录时关联分支和来源，不擅自选一条或要求单 choice |
| 模型窗口／输出限制、计数器和请求准入 | 提供编辑后的上下文和必要测量，保持内容／引用正确，不另建模型策略或静默裁剪 |
| 宿主工具执行与权限 | 编辑候选范围、WB／CB、来源锚、操作账本、PVI、顺序与版本校验、发布／回放 |
| 原生会话与上下文浏览 | 将实际采用的编辑投影及其原生消息关联交回宿主；SIC 自有前端可查看完整编辑过程 |

SIC 内部仍需处理自己引入的并发、冻结、幂等、候选验证和存储限制；这些不等于重新规定整个 Provider 请求的 choice、流式或模型准入政策。独立演示 runner／模型执行器可以作为可选宿主存在，但不能成为透明 Core 的必经路径。

## 4. 流与多结果

不把 SSE 收到后整体缓冲成一个响应再伪称保持了原生流行为。不改原生事件格式，不因编辑而重新生成 reasoning 或其他不透明协议元数据。

对仍在生成的文本、未闭合工具组或多候选返回，识别可编辑边界和归属是 SIC 的问题；选择哪个响应、何时请求下一步等原有策略由 Harness 管理。已经对宿主可见的输出与已经发布的 CB 不原地回写。

## 5. 可见性不是只改线上的 JSON

如果仅在 Harness 看不到的代理里改 Provider 请求，而宿主仍只展示原历史，尚未满足用户要求的上下文可浏览性。应使用目标 Harness 支持的请求投影、会话事件、上下文视图或等价接口，关联原始材料与实际发送内容；保留原生工具和消息身份。

SIC 前端展示 source → WB → 编辑操作／候选 → CB／活动表示 → 原生请求与响应关联。展示这些过程不要求将模型调用改造成独立 Chat 网关。

## 6. 本次源码事实，非永久限制

核对提交 `9187a53` 时，`protocol.rs` 有 Chat、Responses、Anthropic 的保守 decode／encode 及不可变 sidecar；但严格字段白名单、`source.ingest` 仅接 Chat、`provider.rs` 强制非流式／单 choice 和重建请求，使它尚未满足上述透明边界。模块定义与 roundtrip 测试不能据此说主链路已经支持全部协议／功能。

后续适配先查当前实际实现，复用已有同协议解析／重包能力，移除或旁路越界的执行政策；不要重复制造跨协议转译，也不要把用户的目标当作当前实现已经完成的事实。
