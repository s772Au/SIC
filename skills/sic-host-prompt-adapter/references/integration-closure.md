# 适配实现的闭环验收

此检查面向任意 Harness 和本次 SIC 版本。接口名、事件名、原语支持及存储布局从实际源码提取，不照搬某个宿主示例。提示词输出与实现接通分别验收；发现闭环缺失就修复实现或明确未完成，不能用更强的教学掩盖。

## 找到真正读写状态的路径

对每种被兼容替换的能力，定位：谁产生调用、谁取得执行权、谁启动外部执行、谁报告观察、谁持久保存状态、谁消费结果、谁决定下一轮、UI 从哪里读取。保留原生名称／schema 的工具门面只是其中一环。

- Goal 工具已写入 SIC，但原生自动续作 driver 仍读取旧 GoalService，不算接通。调度可以继续由 Harness 执行，但必须读取同一权威状态，并上报真实轮次、停止、恢复和分叉事件。
- 后台／peer／workflow 必须在派发前持久记录稳定逻辑调用身份与执行租约。执行后才登记留下崩溃窗口；未知执行不可用换 ID 重派来“恢复”。进程执行器可以保留，完成／取消／结果回收／采用要可追踪。
- 原生 UI 和其他内部消费者也需读取权威状态或有回执的派生投影。不要只替换模型看得到的工具，而让后台 driver、命令或 UI 继续写另一套状态。
- 沿真实 Agent 循环向前、向后检查自动摘要、compaction、工具结果 pruner、历史裁剪及手动压缩命令。它们可能在最终模型接点之前改写来源，不能因为模型工具表已融合就漏掉。被 SIC 替代的内容编辑统一到同一调度／发布路径；宿主容量政策、附件 offload 和真实执行资源仍保留其职责。
- 按会话确定压缩权威：未启用 SIC 时保留原生自动、手动及局部压缩；从头启用 SIC 时让这些全局压缩入口交给 SIC 持续编辑、递归发布和共同采用，防止两套机制重复处理。原生位置 region 没有可靠 CB 区间映射时明确拒绝并保留材料，这属于局部接口兼容边界，不证明 SIC 核心压缩缺失。普通历史转入 SIC 是独立、显式的迁移功能；不得由局部压缩、恢复或普通绑定悄悄触发。
- 当本次 SIC 启用递归策略时，验证当前 Harness 调用会实际触发高阶生成，再发布并共同采用。外部评测脚本能完成、或主接点只读取已有高阶块，都不足以证明生产接线闭环。优先让 Core 规划与校验、Harness 使用原生调用执行；不要在兼容层再造另一套分组器或偷偷回到固定 Provider 执行器。

## 限定本轮候选，保持旧前缀

完整原生请求通常包含公共指令、既有 CB、历史及新材料。可解码文本不等于可编辑文本。由宿主真实消息身份与已采用投影绑定本轮新材料及既有 CB；Core 持久保存允许编辑的锚并在提交、发布和重放时执行保护，不能只依赖 Editor 提示词。

实际验证第二轮：旧 CB 原文／原生锚不变，仅新材料进入 WB，新 CB 不再次包含旧历史；越权改旧 CB、伪造绑定和撤销依赖均被拒绝。迟到材料进入正确新边界或程序归属，不回写已经发布的 CB。

## 重试与采用的证据

- 同一宿主请求重试不得重复触发 Editor、登记来源或发布 CB。绑定真实 session/turn/request 身份与完整来源／范围指纹；相同输入复用已采用结果，同键换内容拒绝。
- 不透明原生载体可能受 JSON 归一化影响；若传输层承诺保留原始字节，使用原 wire 摘要及锚补丁验证。不要用重新 stringify 后相等来证明原始载体未变。
- 原生候选、已收到编辑、已发布 CB、已发送 Provider、已返回响应、任务结果被请求者采用分别记录。来源证明中的 unit 集合需唯一、按实际顺序且属于授权范围；不能重复 unit 或换序拼出另一个摘要。
- 发布产生“允许采用”的证明之后，检查真正的请求者是否在实际上下文采用接点写回采用回执；资格不能替代状态推进。删除、转交到以后边界和请求重放应分别验证，不能误记或重复采用。
- 采用证明绑定实际请求快照／cut。递归覆盖不等于内容仍在 P 中：逐阶删除或转 V 后不能继续沿低阶资格标记采用。复用当前编辑引擎的真实存活索引，允许合法旧在途快照；资格探测保持只读，权限错误不能吞成普通“不采用”。
- Harness 原有模型准入／等待上限可继承，但不凭空增加 SIC 模型配置或人工确认。事务版本、来源、权限、发布与自有执行租约检查是 SIC 的必要职责。

## 用真实接点验证

至少跑一条实际 Harness registry→角色激活→原生调用序列化→SIC 事务／发布→原 transport→原响应解析的隔离路径，以及一种生态状态从产生到 driver／UI 消费的路径。网络 Provider 可以用本地 fixture 替代，但准确注明测试边界。只 mock 自己设计的函数签名不能证明真实 Harness 接线。

支持多种原生 API 时，逐条沿真实 Adapter 验证完整任务、工具续轮、低／高阶发布与自动采用、后续请求及恢复。接通一条路径、另一条只探活，不能报告全部兼容。源码中的 Adapter 名称可能与产品统称不同，记录实际实现和版本。外部 Provider 拒绝某 API 或媒体时，保留能力拒绝证据；本地协议 fixture 通过证明 SIC 接线，不能替代外部模型的真实能力验收。

递归与原生压缩接线必须组合验证：按本次策略连续跨阶并继续增长，检查实际 Worker／Editor 请求、尾部保留、在途快照、重开及未知执行；再从宿主自动、溢出和手动入口确认它们抵达同一闭环。辅助模块和端口 spy 的测试应与完整主入口测试分开报告。

同条件提示词比较保留原始输出，并把编辑批次交给实际 SIC 校验器；同时报告原生、追加与融合的结果。若融合与追加打平或正文更长，应如实记录，不能把格式通过、篇幅变化或静态冲突分析写成效率提升。

## 来源、角色与安装生命周期

原生工具结果归入 CB 后，既要保留调用关联，也要让模型知道正文现在表示在哪里。空的原生结果占位不能被误读为“工具实际返回空”。以本次 Core 的真实 P 存活索引、不可变宿主消息身份与实际工具调用关联建立只读来源视图；覆盖关系不等于内容保留，用户自称工具结果也不授信。混源压缩段只能称派生表示，不能将整块正文授信为某个工具的返回值。字节范围必须来自实际编辑引擎，不能靠 JS 字符串查找或相同文本猜测。

WB 输入本身也要保留可辨识的来源角色、真实调用关联和原生错误标志；高阶 WB 标明低阶派生关系。Editor 本轮未调用某工具，不能推出宿主或 Worker 未执行它；I 中的派生判断不能改写已验证的工具返回事实。工具已返回也不等于命令成功或后台任务终止，仍使用本次真实状态契约。空占位若会被误读，应以明确的宿主只读指针表达归档位置，标明不是原输出或一次新执行，且不重复摄入。

共同来源视图应对角色一致、绑定当前 cut，并排除下一轮新材料摄入。历史 I/CB 中可能包含旧角色的自述；本次可信角色授权应在宿主支持的位置明确覆盖它们，保留原 I 数据与校验，不清洗历史来伪造一致性。

检查卸载、依赖重载与部分安装失败：已冻结提示词或已采用 SIC 上下文的 Agent 不能因中间件被移除就静默恢复原生执行。宿主需在该 Agent 的生命周期中保留拒绝路径、检查在途最终发送，并按实际接口取消/排空执行；重新启用须重新校验组合。未选中的 Agent 不受影响。

交付需要实际可装配入口。目标宿主只支持 JSON/YAML 配置时，不能仅给需要临时编程的回调示意便称安装完成。凭据仍由宿主管理；可信 Session/chain/scope 绑定、持久恢复与原生 flush 必须有本次可执行装配，缺口单列。
